# 出站 Webhook 提醒

## 范围

通知设置提供一个「Webhook 提醒」入口。首批平台为钉钉、飞书、Slack 和 Discord。用户可以同时保存多个目标，每个目标独立启停、删除和发送测试消息。已有的外部信号接收接口 `/api/webhooks/receive/{publicId}` 不变。

正式发送范围是价格提醒、策略信号、交易成功和交易失败。登录、账号安全、系统告警以及管理员专属事件不发送。交易结果只发给该用户自己启用的目标。价格提醒仍尊重单条提醒选定的渠道，不因为开启了全局目标就把未选 Webhook 的提醒发出去。

## 实现取舍

- 继续保留两个独立入口会让 Slack 和 Discord 的设置继续膨胀；开放任意 URL 虽然灵活，但会扩大服务器对外请求的攻击面。首版采用统一入口和固定平台适配器，不接收任意目标。
- 设置表与入站 Webhook 分开；列表只返回目标名称、平台、状态和脱敏信息。Webhook 地址和签名密钥加密存储，禁止记录明文。保存和实际发送前都校验 HTTPS、平台主机及路径；不跟随重定向。测试发送使用固定无敏感内容的消息并限频。
- 在事件产生处入队，由后台分发。价格提醒走 `AlertNotificationBridge` 的渠道选择，策略信号和交易结果走统一事件入口。每个目标有自己的投递记录及重试状态；同一事件与目标组合去重。失败或停用一个目标不影响其他渠道，停用或删除后不再投递待发送项。
- 复用队列的租约、退避和清理模式，不复用 Bark 或 FCM 的目标及凭据。平台适配器负责消息、签名和响应判定；限流与可恢复错误重试，永久错误不反复重试。

## 界面与验收

按平台显示填写说明；仅钉钉和飞书显示可选签名密钥。价格提醒新增可选的 Webhook 渠道，现有短信和电话仍只读，感知设置仍隐藏。现有钉钉和飞书偏好没有可发送的地址，不据此自动创建或启用目标。

验收覆盖四平台请求契约、凭据脱敏、恶意 URL 拦截、事件范围、用户隔离、渠道过滤、重复事件、单目标失败和停用后不发送。真实平台测试消息需用各平台的专用测试群和测试凭据。
